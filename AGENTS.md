# AI Anti-Slop: agent instructions

AI Anti-Slop is a Manifest V3 Chrome extension (plus a generated userscript) that hides x.com posts by accounts on self-updating AI-reply spam lists, and can optionally mute them through X's own menu. It uses no X API. A small Cloudflare Worker with a D1 database (`server/`) publishes the "readers' list" the extension reads. The code is plain ES modules and `.js` files with no bundler and no framework; the only dev dependencies are `linkedom` and `playwright-core` (`package.json`). The repo is public: keep secrets, tokens, personal paths and private hostnames out of every file (`CONTRIBUTING.md`).

## Repo map

- `src/lib.js`: pure logic shared by every runtime and the tests (list parsing, update guard, hide rule, bot rows, muting rules and caps).
- `src/content.js`, `src/background.js`: the page script and the MV3 service worker (feed fetch, alarm, one background tab per mute visit, label storage).
- `src/popup.*`, `src/settings.*`: popup and settings page. `src/userscript-adapter.js`: the userscript's storage shim.
- `dist/x-slop-hide.user.js`: generated by `scripts/build-userscript.mjs` and committed. Never edit it by hand.
- `manifest.json`, `package.json`: the version lives in both and must match.
- `test/*.test.mjs`: extension tests (`node:test`; DOM tests run the real `content.js` under linkedom). `server/test/`: server tests against `node:sqlite` in place of D1.
- `server/`: the readers' list Worker (`server/README.md` has the rules, endpoints, deploy steps). `server/migrations/` holds the D1 schema.
- `scripts/package-store.mjs`, `scripts/store-screenshots.mjs`: Chrome Web Store zip and screenshots. `store/listing.md`: what to enter in the store dashboard.
- `PRIVACY.md`, `README.md`, `docs/TESTING.md`: user-facing docs and the log of real-browser runs.

## Setup and commands

Node 22 is what CI uses (`.github/workflows/test.yml`); the pinned package manager is `pnpm@12.21.0`. No linter or formatter is configured.

```
pnpm install --frozen-lockfile --ignore-scripts   # what CI runs
pnpm run build       # rebuild dist/x-slop-hide.user.js from src/
pnpm test            # node --test 'test/*.test.mjs' (no browser needed)
pnpm run check       # build --check, node --check on the userscript, extension tests, server tests
pnpm run package:store   # store zip of HEAD into build/ (gitignored)
```

CI runs the same steps as `pnpm run check`, split into separate workflow steps (`.github/workflows/test.yml`). The server tests need nothing from `server/node_modules`; `wrangler` is only for `wrangler dev` and deploys.

## Rules and traps

- Any change under `src/` that reaches the userscript needs `pnpm run build` and the regenerated `dist/x-slop-hide.user.js` in the same commit; `check` fails on a stale file. Userscript managers update only when `@version` rises, and `@version` comes from `manifest.json` (`scripts/build-userscript.mjs`).
- The userscript keeps its old `@name` and `@namespace` (`x-slop-hide`, old repo URL) and its file path on purpose, so installed copies keep updating. Do not rename them (comments in `scripts/build-userscript.mjs`).
- Keep logic in `src/lib.js` where tests can reach it; `content.js` and `background.js` are tested through linkedom and an in-memory `chrome` stub (`test/dom.test.mjs`, `test/wiring.test.mjs`).
- Those tests cannot catch X changing its markup. After a change to selectors, check on real x.com and say so, or say you could not (`README.md` "Development", `docs/TESTING.md`).
- Test fixtures use made-up handles. Do not put real account handles in tests.
- Store permissions must not grow without intent: 0.10.0 matched 0.9.0's permissions so updates show no new warning (`git log`, #87). `scripts/package-store.mjs` refuses a manifest `key`, a name over 75 or a description over 132 characters, and a `manifest.json` version that differs from `package.json`.
- Keep the docs true: `README.md` when behavior changes, `PRIVACY.md` when what is stored or sent changes, `store/listing.md` when store text should change (`CONTRIBUTING.md`).
- Server rules (list thresholds, `RULES` in `server/src/core.js`) are read by the tests, not copied; change them in one place and keep `server/README.md` in step.

## Release and store (document only; do not run)

Releases, store submissions and server deploys are done by maintainers, never by an agent. A release bumps the version in `manifest.json` and `package.json`, rebuilds the userscript, and updates the lines that name the version in `PRIVACY.md` and `store/listing.md` (see #87). The store zip is built from a commit with `node scripts/package-store.mjs --ref origin/main`, never from a working tree; `store/listing.md` lists the dashboard fields. The Worker deploys with `wrangler deploy` per `server/README.md`. Do not run `wrangler login`, `wrangler deploy`, or any upload, publish or submit step.

## Definition of done

- `pnpm run check` passes (extension tests and server tests included), and `dist/` is regenerated if `src/` changed.
- The PR says what was broken, which test shows the fix, which checks you ran, and what you could not test, as `.github/pull_request_template.md` asks.
- User-facing docs touched by the change are updated.
- CI (`test` workflow) is green.

Verify your work. If any command fails or you couldn't run it, say which and why.
